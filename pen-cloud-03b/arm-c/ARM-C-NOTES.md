# ARM-C-NOTES: PEN-CLOUD-03-B Arm C (Foundation-generated React)

Arm C = React generated by a deterministic generator from the accepted DSC r1, SAC, Penpot structure observations (OD-41), copy.json and the Source Sans 3 files. Nothing else was read (isolation rule: no Relume source, no Arm A/B material, no foundation-engine, no tool-result files, no web search).

## Layout

- `generator/` TypeScript (tsx): `generate.ts`, `lib/*` (tokens, css builder, observation query, SAC index, Tailwind-string parser), `emit/*` (one emitter per component). Run: `pnpm generate`, `pnpm generate:verify`.
- `app/` Vite 7 + React 19 SPA, minimal path router (`src/App.tsx`), port 4304. `app/src/generated/**` is generator output (35 files + manifest).
- `ssr/` TanStack Start (real, not the fallback) on Vite 8, port 4305, `server.mjs` = small Node http adapter around `dist/server/server.js` (`fetch` handler) plus static `dist/client`. It imports the generated components through the alias `@generated` -> `../app/src/generated` (no copies). One splat route `$.tsx` + `index.tsx` resolve paths against the generated `routes` table, so both arms serve the same components from the same route list; unknown paths give 404 in SSR.
- Root: pnpm workspace (`app`, `ssr`), one `pnpm-lock.yaml` (workspace lockfile), Biome 2.5.15 (`pnpm lint`), strict TS.

## Generator outputs (`app/src/generated/`)

`tokens.css` (all 32 DSC tokens as `--fs-<id minus fs.token.>` with dots to dashes; md/sm overrides as `@media (max-width: 1023.98px / 767.98px)` from the DSC breakpoints; plus `--fs-layout-container-max` and `--fs-layout-side-padding`), `tokens.ts` (typed), `copy.ts`, `runtime.ts` (identity attrs, SSR-safe `useMediaQuery`, placeholder data URI), `base.css`, `Button|Navbar|Hero|Features|Testimonials|Cta` (.tsx + .css), `routes.tsx` + `routes.css`, `generated-manifest.json`. Fonts are copied byte-for-byte (checked against fonts/MANIFEST.json) to `app/public/fonts` and `ssr/public/fonts`; `generate:verify` diffs all three trees.

Manifest holds: DSC id/revision, sha256 of every input, sha256 of generator sources, sha256 of every generated file, tokens referenced per file, SAC coverage (57/57 annotations consumed; generation fails otherwise), the `ungoverned` list (74 entries with value, reason, source) and the computed `designObservationVsIntent` list (20 entries).

Token-integrity self-check (inside the generator, fails the build): every `font-*`, `line-height`, `letter-spacing`, `border-radius`, `color`, `background`, `border-color` declaration must be `var(--fs-*)`, no hex literal may appear in CSS, and every px/vw/vh/rem/% literal must have been registered through `ctx.lit`/`ctx.sp`. `ctx.sp` substitutes the matching spacing token (gap.4/6/8) when an observed spacing equals one exactly, else registers a literal.

## Design decisions

- SAC roles drive element choice (`SacIndex.tag`): navigation->nav, hero->header, heading->h1/h2/h3 (by level), feature/testimonials/cta-section->section, cta->button type=button, link->a href="#". `data-fs-id` = SAC desktop logicalId, `data-fs-bbc` = comma-joined bbc, `data-fs-penpot` = desktop Penpot shape id (cross-checked against DSC `external.penpot.desktop`; mismatch fails generation). Because one React component serves all breakpoints, the tablet/mobile twins are also emitted (`data-fs-id-tablet|mobile`, `data-fs-penpot-tablet|mobile`) and `data-fs-component` carries the DSC component id (e.g. `fs.section.hero`, `fs.component.button.primary`). On `/button` the buttons carry the DSC component id and `mainShapeId`.
- Navbar: the identity attributes are on the root `<header>` (SAC "navigation" board = the whole Navbar17), with the `<nav aria-label="Main">` inside it. Hero is `<header>` (SAC landmark) inside `<main>`, so it is not a second banner landmark.
- Hero parallax is implemented as specified: `useScroll({target: section, offset: ["start start","end end"]})` -> `useSpring(..., {bounce: 0})` -> `useTransform` to the two columns (`data-fs-motion="images-left|right"`), 0%->-85% / 0%->-60% desktop, -12.5%->-85% both columns below 768 (JS media query from DSC `interaction.breakpoint`), section 300vh (150vh below 768) via CSS media query (SSR-safe), sticky 100vh stage with overflow hidden, right column opacity 0.75, images laid out by parsing the DSC `imageLayout` Tailwind-style strings into CSS (verified in the browser: left column ends at -85% of its own height; 6 images). `prefers-reduced-motion: reduce` removes the transform (style not applied + CSS `transform: none !important`); the section keeps its height.
- Navbar hamburger follows the DSC hamburger spec (top/bottom line width 0/100% with the given durations, delays and easings; two middle lines rotating 135/45 deg; panel via AnimatePresence, opacity 0/1 in 0.3s, `top-full`, height `calc(100vh - 4rem)` / `calc(100vh - 4.5rem)` from md). Button has `aria-expanded`, `aria-controls="fs-navbar-menu"`, a label that flips Open/Close menu; Escape closes. Menu is closed on first render, so `/navbar` is closed in SSR and SPA.
- Features: 3 columns at md+ with two 1px divider elements between columns (grid `1fr 1px 1fr 1px 1fr`, gap = gap.8 token), 1 column with 1px rules at sm. Testimonials: grid 1 / 2 / 4 columns (sm/md/lg), quote cards span 2 from md, 32px (gap.8) gaps; card at index 2 gets `order: 1` below lg.
- Buttons: `<button type="button">`, height 48, padding 0 24px, 1px border (DSC geometry), label size/radius/fills from the DSC bindings.
- Placeholders: images are `<img>` with an inline SVG data URI (#d9d9d9); logos/icons/stars are `#000` divs from `--fs-color-neutral-darkest`. No network request is made (verified by request logging in Chromium at three viewports on both servers).
- Only `/header80` and `/page` contain an h1 (SAC hero h1). The other component routes have h2 headings and no h1 (no invented hidden heading, to keep text identical across arms); at most one h1 per page holds everywhere.
- `/` renders a small index (not part of the contract); unknown SPA paths render a "Not found" view with HTTP 200 (preview server SPA fallback), unknown C-SSR paths return 404.

## Design observation vs intent (DSC wins; full computed list in the manifest `designObservationVsIntent`)

1. Responsive type: Penpot tablet/mobile boards keep 56/48/32px for h1/h2/h4 text; DSC tokens have md 48/40/28 and sm 40/36/24. DSC wins (heading sizes shrink with the breakpoint).
2. Secondary button: Penpot instance has no fill; DSC binds fill to `color.scheme.foreground` (#fff). DSC wins (white background, visually identical on a white page).
3. Testimonials grid gap at sm: Penpot 24px, DSC gridGap = gap.8 (32px). DSC wins.
4. Features sm: Penpot has gap 0 and rule lines between rows; the gridGap token is applied only between columns (md+).
5. Button width: Penpot 95px (inner stroke inside the padding) vs CSS border + padding (rendered 96px at 16px Source Sans 3); the DSC geometry (padding 24, stroke 1) was implemented with a real border.
6. Hero text block sits 63.5px (lg, md) and 104.5px (sm) below vertical centre in the Penpot boards. The DSC gives no offset, so the text is centred in the sticky stage. Not reproduced.
7. Containers: DSC lists 1280/691/337; 691 and 337 are the canvases minus 5% padding. Implemented fluid: max-width 1280px inside 5% side padding (a hard 691px max would break widths between breakpoints).
8. Navbar menu: DSC says 8 links, copy.json has 4. copy.json wins.
9. Testimonials order: the owner brief says the index-2 quote card is ordered last below lg; the Penpot tablet/mobile boards show DOM order (logo, logo, quote, quote, logo, logo). The owner statement was followed (order: 1 on card index 2), which is not what the Penpot boards show.

## Assumptions made because of the isolation rule (gaps in the permitted inputs)

- A1: Menu panel link padding (16px) and the bottom-bar padding (32px) are not specified; chosen from the spacing tokens. The menu is closed in all contract routes.
- A2: The "Contact" link label in the menu bottom bar is not in copy.json; the text "Contact" was assumed (visible only when the menu is open). The social links are named "Social link 1..5" (sr-only text).
- A3: Social icon placeholder size 24x24 (DSC gives only "5 social icons").
- A4: z-index values, focus ring (2px solid `scheme.border`, 2px offset), hover underline on the feature link, and 8px label/chevron gap are mine.
- A5: Hero vertical alignment of text (centred) - see item 6 above.
- A6: `useSpring` with `{ bounce: 0 }` and no duration uses motion's default spring duration, so the transform lags the scroll position by up to roughly a second; the scroll probe waits 600 ms and may read an intermediate value (my own probe waited 1200 ms and read exact -85%/-60% values at p=1).
- A7: Which "index-2" card is meant is taken as `copy.testimonial37.cards[2]` (first quote card).
- A8: Hero images are absolutely positioned columns of width 100% so the DSC vw offsets are relative to the viewport; right-column items are end-aligned (`align-items: flex-end`) so `right-[..vw]` offsets move them left from the right edge. Both reproduce the observed Penpot positions (checked arithmetically at 1440: 22vw=317px, 58vw=835px, etc.).

## Known limitations

- `ssr/src/routeTree.gen.ts` is generated by the TanStack plugin at build time (not by the Arm C generator, not in FROZEN).
- Hydration: `useMediaQuery` returns false during SSR/hydration, so on a phone the parallax starts at the desktop range for the first paint and corrects after hydration.
- The sticky stage uses `100vh` (spec "h-screen"), which on mobile browsers with dynamic toolbars may differ from the visible height.
